# Plugin API 16: angesehenes und nächstes Pattern lesen

Stand 5. November 2026. **Gemessen** im Emulator mit Hacktribe 2.02 (eigene Datei), Korgs Original 2.02 rot und blau,
jeweils mit dem BLECH-Satz. Fälle: `tools/emu/plugin_api16_cases.py` (läuft als Gruppe von `remote_cases`). **Am Gerät
nicht geprüft.**

## Was gelesen wird

| Aufruf | Quelle | Wert |
|---|---|---|
| `korg.read.viewedPattern()` | Zeigerzelle der Pad-LEDs (`0xC0691388`, blau `0xC056B624`, siehe [Ansicht des nächsten Patterns](2026-10-25-pattern-ansicht.md)), bei `+4` des Zugriffsobjekts das Pattern | liegt es im Bankbereich (`Bank + Nummer * 0x4000 - 4`), ist die Nummer `(Zeiger + 4 - Bank) >> 14`, sonst die Nummer des laufenden Patterns (Player, `+0x318`) |
| `korg.read.nextPattern()` | Zustand des Patternwechsels: `0xC0180F04` bestätigt (1), `0xC0180F08` die Nummer; dazu das Wartend-Flag der Auswahl bei `+0x341` (`0xC06B2108`, blau `0xC0582F78`; es ist dasselbe Objekt, dessen `+0x318` `korg.read.pattern` liest) | die Nummer, wenn bestätigt und die Firmware sie noch hält, sonst -1 |

Die Zelle liegt auf allen drei Firmwares an den Stellen, die `tools/patch/pattern_switch.py` und `data/synth-map/` schon
führen; der Zustand des Patternwechsels liegt in eigenem RAM und ist auf allen drei Firmwares derselbe. Ohne den Patch
steht dort `FFFFFFFF` (hergeleitet: das Bild ist dort leer), `korg.nextPattern` gibt dann -1 und `korg.viewedPattern` das laufende Pattern.

`korg.selectedPattern` (`korg.read.pattern`) liest die gewählte Nummer der Auswahl (`+0x318`). Sie ist beim Blättern
dieselbe wie das angesehene Pattern, bei ausgeschaltetem PATTERN CONFIRM aber die der Firmware-Warteschlange, während das
Display das spielende zeigt. Darin unterscheiden sich die beiden.

## Gemessen (Prüfungen `plugin_api16:*`)

Ein Plugin liest in jedem Frame `korg.viewedPattern`, `korg.nextPattern` und `korg.selectedPattern`. Pattern 0 spielt,
Werte als (angesehen, nächstes, gewählt):

| Fall | Ergebnis auf Hacktribe, rot und blau |
|---|---|
| spielt, nichts bewegt | (0, -1, 0) |
| Rad +3, nicht bestätigt | (3, -1, 3), das spielende Pattern bleibt 0 |
| MENU | angesehen 3, nächstes 3 |
| Rad +2 nach der Bestätigung | angesehen 5, nächstes 3 |
| EXIT, EXIT | (3, 3), dann (0, -1) |
| bestätigte 2, Sequenzende | angesehen 2, nächstes -1, spielt 2 |
| gestoppt, Rad +5 | angesehen 5, nächstes -1 (die Firmware lädt sofort) |
| PATTERN CONFIRM aus, Rad +3 | (0, -1, 3): die Warteschlange der Firmware ist keine Bestätigung |

## Grenzen und offen

- Am Gerät nichts geprüft.
- Ohne den Patch des Patternwechsels (nicht im Satz) bleibt `korg.nextPattern` -1, auch wenn die Firmware ein Pattern vormerkt.
- Gestoppt mit ungespeicherten Änderungen blättert das Rad wie beim Spielen (`VIEW:`), `korg.viewedPattern` zeigt das
  geblätterte Pattern; dieser Fall ist im Emulator nicht eigens geprüft.
