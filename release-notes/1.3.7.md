BLECH 1.3.7 und die App 1.3.7.

**Neu**
- Die Electribe startet mit dem Pattern, das zuletzt gewählt war. Hältst du beim Einschalten EXIT, startet sie wie früher mit 001.
- BLECH > FEATURES > INIT PATTERN: du wählst, welches Pattern INITIALIZE PATTERN in DATA UTILITY kopiert. So beginnt ein neues Pattern mit deiner eigenen Vorlage. FACTORY und EXIT beim Einschalten behalten die Vorlage von Korg.
- Beides gibt es auch für die blaue Electribe.
- Plugins: `korg.get` und `korg.set` erreichen Einstellungen über einen Baum von Objekten, der erste Wert ist die Helligkeit des Displays (Plugin-API 10).
- Die App zeigt die Release Notes älterer Versionen, auch ohne Internet.
- Konsole: die Probe eines Skripts startet den Emulator hinter einer angeschlossenen Electribe, statt die Verbindung zu trennen.
- Die MIDI-Diagnose nennt den Windows-Treiber von Korg, wenn er im Weg ist. Mit ihm kommen die Antworten der Electribe nicht an, mit dem Treiber von Windows schon.
- Der volle Test im Patcher ist schneller.
- Für Selbst-Hoster: der Editor läuft in einem Docker-Container und hinter einem Reverse Proxy, die Karte liegt dabei im Ordner `./SD`.

**Behoben**
- Der volle Test im Patcher schlug fehl (Menü, Pattern-Schalter, TAP Motion, Notenassistent, Würfeln), wenn im Emulator Patterns gespeichert waren, etwa nach einem Pattern-Import. Die Prüfungen der Patches laufen jetzt immer auf einem leeren Flash, deine Emulator-Patterns bleiben unberührt.
- Nach einem App-Update konnten zwischengespeicherte Prüfergebnisse der alten Version weiterbenutzt werden.
- Windows: die Electribe wird auch gefunden, wenn Windows ihre Ports nach der Buchse benennt.
- Plugins: `korg.store` speichert auch, während das BLECH-Menü offen ist.
- Plugins: ein in PLUGIN EDIT ausgeschaltetes Plugin bleibt nach dem Neustart aus, auch mit vielen Plugins auf der Karte. Bisher konnte das Speichern die Liste der ausgeschalteten und erlaubten Plugins durcheinanderbringen, und war sie voll (16 Einträge), wurde das Ausschalten nicht gespeichert.

## English

BLECH 1.3.7 and the app 1.3.7.

**New**
- The Electribe starts with the pattern that was selected last. Hold EXIT at power-on to start with 001 as before.
- BLECH > FEATURES > INIT PATTERN: pick the pattern that INITIALIZE PATTERN in DATA UTILITY copies, so a new pattern starts from your own template. FACTORY and EXIT at power-on keep Korg's template.
- Both also work on the blue Electribe.
- Plugins: `korg.get` and `korg.set` reach settings through a tree of objects; the first value is the display brightness (plugin API 10).
- The app shows the release notes of older versions, also offline.
- Console: a script's trial run starts the emulator behind a connected Electribe instead of disconnecting it.
- The MIDI diagnostics name Korg's Windows driver when it is in the way. With it the Electribe's replies do not arrive; Windows' own driver works.
- The patcher's full test is faster.
- For self-hosting: the editor runs in a Docker container and behind a reverse proxy, with the card in the `./SD` folder.

**Fixed**
- The patcher's full test failed (menu, pattern switch, TAP Motion, note assistant, dice) when patterns were stored in the emulator, for example after a pattern import. The patch checks now always run on a blank flash; your emulator patterns stay untouched.
- After an app update, cached check results of the old version could still be used.
- Windows: the Electribe is found also when Windows names its ports after the jack.
- Plugins: `korg.store` saves also while the BLECH menu is open.
- Plugins: a plugin switched off in PLUGIN EDIT stays off after a restart, also with many plugins on the card. Saving could mix up the list of switched-off and allowed plugins, and when it was full (16 entries) the switch-off was not saved.
